ИИ‑агент для бухгалтерии и системного администрирования

Чьи задачи это закрывает.

Бухгалтер: требования ФНС в срок; завал первички; сверки; выписки.
Сисадмин: ночные сбои; бэкапы; рутинные настройки.
Руководитель: снять эти часы и риски — без найма.

Что предлагается.

ИИ-агент — программа на компьютере сотрудника.
Ей ставят задачу обычным текстом.
Она читает документы, сверяется с 1С, готовит ответы, проводки, настройки.
Правило одно: агент готовит — человек проверяет и утверждает.

Данные не утекают.

Между агентом и ИИ стоит фильтр обезличивания.
Наружу уходят подменённые имена, ИНН и счета — по виду настоящие.
Словарь замен остаётся только у вас. Ответ восстанавливается обратно.
Подмена не разрешилась — выдача останавливается.

Три варианта (можно совмещать):

  1. Зарубежный ИИ (Claude). Сильнейший сегодня. ≈1,6–19 тыс ₽/мес на место.
    Из России официально недоступен: обходной канал — риск блокировки;
    легально — зарубежное юрлицо.
  2. Российский (GigaChat, Яндекс). Данные в России.
    Сотни–тысячи ₽/мес. Начать можно бесплатно.
  3. Свой компьютер с видеокартой (~200–400 тыс ₽ разово).
    Данные не покидают офис. Обязательный резерв для 1 и 2.

Старт — без затрат.

Открытая оболочка + бесплатные лимиты моделей.
Первый месяц агент только предлагает.
Приёмка: ноль изменений без подтверждения,
ноль неразрешённых подмен, полный журнал.

1. Что это и как работает

ИИ-модель сама по себе только отвечает текстом. Агент — это модель плюс программа-исполнитель. Цикл простой: модель предлагает шаг — программа выполняет (открыть файл, запросить 1С, запустить команду) — результат возвращается модели — следующий шаг.

Так это описывает Anthropic: «Claude Code is an agentic coding tool that reads your codebase, edits files, runs commands» — читает ваши файлы, редактирует их, запускает команды. «Кодовая база» здесь — любые рабочие файлы, включая 1С.

Важно: агент работает на вашем компьютере — «runs locally in your terminal and talks directly to model APIs». В интернет уходят только тексты запросов. Поэтому один фильтр на этом пути закрывает весь канал утечки.

Подключение к 1С не требует доработок. Платформа сама даёт веб-доступ: «REST интерфейс позволяет читать данные 1С:Предприятия, изменять их, создавать новые» (v8.1c.ru). Отчётность — через API оператора: «Отправить сформированную отчетность в контролирующий орган. Отследить и завершить документооборот» (Экстерн; так же у СБИС).

2. Как выглядит рабочий день

Бухгалтер: «Разбери требование ФНС, сверь с базой, подготовь опись и проект ответа, расхождения — таблицей». Агент получает требование по API (есть автопроверка Check-Demand), сверяется с 1С, собирает пакет. Человек 10–15 минут проверяет и утверждает. Вручную этот цикл обычно занимает часы.

Первичка: скан → распознавание («автоматизировать ввод первичных бухгалтерских документов в базу», ocr.1c.ai) → проводки пакетом на подтверждение. Сверка: акты в формате ФНС (с 2022) сверяются автоматически. Выписки: штатный 1С:ДиректБанк, 40+ банков.

Сисадмин: «Сайт не открывается — найди причину». Агент читает логи, называет причину и команду починки. Применяет человек. «Настрой ежедневную копию базы 1С с проверкой восстановления» — агент пишет скрипт и расписание, включает после подтверждения.

Польза уже сейчас, без покупки: поверхности у вас есть. OData включается в вашей 1С штатно; API Экстерна и СБИС доступны по договору с оператором; 1С:Напарник бесплатен подписчикам ИТС до 01.10.2026.

3. Как данные остаются под защитой

«ООО „Ромашка«, ИНН 7712345671» → наружу «ООО „Пион», ИНН 7787654324». Формат и контрольные цифры сохранены — модель работает как с настоящими. Словарь «Ромашка ↔ Пион» — только у вас. Ответ вернулся — снова «Ромашка».

Это штатный механизм открытых инструментов. Presidio: «the user/client is holding the entity_mapping … use it for de-anonymization» — словарь замен держит клиент, значит восстановить имена может только он. Готовые шлюзы делают обратную замену прямо в ответе (LiteLLM: «replace the masked token with the user-submitted values»).

Известный сбой класса задокументирован там же: «LLM responses can sometimes contain the masked tokens» — модель может вернуть подмену в искажённом виде. Поэтому правило: неразрешённая подмена останавливает выдачу. Человек видит ошибку — данные не уходят.

Русские реквизиты: ИНН, КПП и счета распознаются правилами с контрольными цифрами; имена и адреса — нейрораспознавателем на обычном процессоре.

Право. 152-ФЗ, ст. 18 ч. 5: базы с персональными данными россиян «за пределами территории Российской Федерации … не допускаются». Бухгалтерия несёт чужие данные и тайну (ст. 102 НК). Отсюда правило на каждый день — даже без этого решения: во внешний ИИ данные идут только обезличенными, словарь замен храните у себя. Для зарубежного варианта дополнительно: «does not train generative models using code or prompts … under commercial terms» — на коммерческих данных модель не учится; есть режим нулевого хранения (Zero Data Retention).

4. Почему агенту не дают полную свободу

Два случая 2025 года. Агент сервиса Replit удалил рабочую базу клиента — «This was a catastrophic failure on my part» (признание самого агента). В помощник Amazon Q через обновление внедрили команду-стиратель (бюллетень AWS-2025-019).

Выводы встроены в решение — и годятся как правила для любого ИИ в компании: рабочая и тестовая среды разделены; любое изменение — сначала вхолостую, потом подтверждение; песочница на уровне операционной системы — «the operating system enforces that boundary for every Bash command»; пароли и базы агенту недоступны. Отраслевая норма та же: агент дежурного сервиса PagerDuty рекомендует действия — применяют люди по утверждённым сценариям. Журнал всех действий — это и приёмка, и защита при разборе.
